# خطة الباك إند (Supabase)

**الوضع دلوقتي:** المراحل اللي في اللعبة بتتحمّل من `LevelSource`، والمصدر
الحالي هو `BuiltInLevels` (المراحل المكتوبة في `levels.dart`). المرحلة بقت
**تتكتب وتتقري JSON**، والتستات بتثبت إن مرحلة عدّت على JSON ورجعت **لسه
بتتحل** — بتعيد تشغيل الحل المسجّل على النسخة المفكوكة، مش بتقارن حقول.

يعني الشغل الباقي عشان Supabase **مش معماري**، هو كلاس بيجيب نص.

---

## القاعدة اللي الخطة مبنية عليها

**اللوكال أصل، والسيرفر بيزوّد بس.**

```dart
LevelsThenExtras(const BuiltInLevels(), SupabaseLevels(...))
```

`LevelsThenExtras` شغالة دلوقتي ومختبرة، وبتعمل تلات حاجات:

1. المراحل اللي بتشحن مع اللعبة **دايماً موجودة**، من غير نت، للأبد.
2. السيرفر **بيضيف بس** — `id` موجود أصلاً بيتتجاهل. رفعة غلط متقدرش تستبدل
   مرحلة اتأكدنا إنها بتتحل.
3. السيرفر وقع؟ اللاعب بياخد الحملة الأساسية **ومفيش رسالة غلط**. لعبة ألغاز
   مبتفتحش لأن CDN تعبان أسوأ من لعبة فيها تلات مراحل أقل.

## الـ Schema

```sql
create table levels (
  id            text primary key,          -- 'press-it-early'
  data          jsonb not null,            -- نفس شكل Level.toJson()
  solution      jsonb not null,            -- تسجيل حل، زي اللي في التستات
  author        uuid references auth.users,
  published     boolean not null default false,
  sort_order    int not null default 1000,
  created_at    timestamptz not null default now()
);

-- الكل يقرا المنشور بس
alter table levels enable row level security;
create policy "read published" on levels
  for select using (published);
create policy "author writes own" on levels
  for all using (auth.uid() = author) with check (auth.uid() = author);
```

**`solution` مش زيادة — هي شرط القبول.** اللعبة عندها بالفعل هارنس بيشغّل
تسجيل حركات على اللعبة الحقيقية (`test/level/solution.dart`). نفس الكود ينفع
يتشغّل **قبل ما مرحلة تتقبل**: مرحلة مالهاش حل بيشتغل مترفعش. ودي حاجة قليل
جداً لعبة تقدر تعملها — إحنا نقدر لأن الظل بيسجّل النتيجة مش المدخل، فالإعادة
مطابقة تماماً.

## اللي فاضل (صغير)

```dart
class SupabaseLevels implements LevelSource {
  @override
  Future<List<Level>> load() async {
    final rows = await client.from('levels')
        .select('data').eq('published', true).order('sort_order')
        .timeout(const Duration(seconds: 4));      // مايستناش النت
    return [for (final row in rows) levelFromJson(row['data'])];
  }
}
```

زائد: كاش على القرص (آخر نسخة ناجحة) عشان التشغيلة الجاية تبقى فورية،
و`timeout` عشان شاشة البداية متستناش الشبكة.

## الباك إند ينفع في إيه تاني — مرتبين بالفايدة الحقيقية

### ١. تيليمتري لتظبيط الألغاز — **دي أهم حاجة**

انت مطوّر لوحدك ومفيش عندك لاعبين تجريبيين. السؤال اللي مش قادر تجاوبه:
**أنهي مرحلة ظالمة؟**

```sql
create table attempts (
  level_id   text, delay_seconds real,
  reloads    int,          -- كام مرة مات/أعاد قبل ما يخلص
  seconds    real,         -- خد قد إيه
  gave_up    boolean,      -- قفل وهو فيها
  died_at    jsonb,        -- إحداثيات الموت
  created_at timestamptz default now()
);
```

من ده تعرف: مرحلة متوسط الإعادة فيها ١٢ مرة = ظالمة. مرحلة ٤٠٪ بيقفلوا فيها =
فيها حاجة غامضة. خريطة أماكن الموت بتوريك **المكان** بالظبط.

ده بيحوّل "هل المرحلة ممتعة؟" من إحساس لرقم — وهو بالظبط السؤال اللي Phase 2
كلها اتعملت عشانه.

### ٢. مراحل من اللاعبين، **متحقَّق منها**

شكل المرحلة data خلاص، فاللاعب يقدر يعمل واحدة. والفرق عندنا: **يرفعها ومعاها
تسجيل الحل**، واللعبة تشغّل التسجيل قبل القبول. مفيش مراحل مستحيلة، ومفيش
مودريشن يدوي للي بيتحل من عدمه.

### ٣. تظبيط عن بُعد

`delaySeconds` رقم في الـJSON. لقيت المرحلة التالتة صعبة بعد ما نزلت؟ تغيّر
الرقم في الداتابيز من غير نسخة جديدة على الستورات.

### ٤. ليدربورد بإعادة متحقَّق منها

نفس آلية التسجيل: أسرع حل مسجّل لكل مرحلة، واللعبة تقدر **تعيد تشغيله**
وتتأكد إنه حقيقي. غش الليدربورد بيبقى صعب لأن الرقم مش مرفوع — التسجيل هو
المرفوع.

### ٥. حفظ التقدّم (Phase 5 أصلاً)

آخر مرحلة وصلتها، تتزامن بين الموبايل والديسكتوب.

## اللي **منعملوش**

- ❌ **تسجيل دخول إجباري.** لعبة فردية. التيليمتري بـ`device_id` عشوائي
  مجهول يكفي، والدخول بس لو رفعت مرحلة.
- ❌ **المراحل الأساسية على السيرفر بس.** اللعبة لازم تشتغل في الطيارة.
- ❌ **استنى الشبكة على شاشة البداية.** timeout ٤ ثواني وكمّل.
- ❌ **مفاتيح في الريبو.** الـanon key بتاع Supabase مصمم إنه public، بس
  الـservice key لأ — ده متحطش هنا أبداً، والـRLS هي الحماية مش الغموض.
