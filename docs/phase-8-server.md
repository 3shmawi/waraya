## ٠) ليه دلوقتي

Phase 7 خلصت: ستاشر مرحلة، والست الصعبين **اتلعبوا بإيد واتحلّوا**. والمرحلة
بقت بيانات كاملة: JSON فيه المستطيلات **وحلّها المسجّل وأفكارها الغلط**، وبتقول
محتاجة إيه (`requires`). ده كان الشرط عشان مرحلة تيجي من بره: البوابة محتاجة
حاجة تشغّلها، والمرحلة بقت شايلاها معاها.

والسبب التاني عملي: عايزين **مراحل كتير**. كل مرحلة جديدة دلوقتي محتاجة بيلد
جديد على كل ستور. سيرفر بيزوّد مراحل = مراحل جديدة من غير بيلد.

## ٢) أهم قرار في الـPhase: البوابة بتشتغل فين

البوابة لازم تشغّل **اللعبة الحقيقية** — `LevelGame` جوه `Playthrough`. ده كود
Flutter/Flame، مش حاجة تتكتب تاني بلغة تانية (نسختين من الفيزيا = نسختين
بيختلفوا، وده بالظبط اللي المشروع كله مبني يمنعه).

و**Supabase Edge Functions بتشتغل Deno/TypeScript** — متقدرش تشغّل Dart ولا
Flutter. فالبوابة مش هتبقى جوه Supabase. الاختيارات:

| الاختيار | إزاي | مع | ضد |
|---|---|---|---|
| **أ. GitHub Action** (المقترح) | cron كل ساعة (أو `workflow_dispatch`): يسحب المراحل `status = pending`، يشغّل `flutter test tool/gate.dart` عليها، ويكتب النتيجة. | مجاني، Flutter موجود أصلاً في الـCI، مفيش سيرفر نشغّله. | مش فوري — ساعة لحد ما مرحلة تتقبل. للعبة زي دي ده كويس. |
| ب. سيرفر Dart صغير | Cloud Run / Fly.io بيشغّل الهارنس headless. | فوري. | سيرفر لازم يتدفع ويتراقب — كتير على مشروع يوم في الأسبوع. |
| ج. البوابة في الكلاينت بس | اللعبة تشغّل التحقق قبل الرفع. | سهل. | **مينفعش لوحده** — أي حد يقدر يرفع JSON من غير اللعبة. ينفع كفحص سريع قبل الرفع، مش كبوابة. |

**المقترح: أ + ج.** الكلاينت بيفحص قبل ما يرفع (عشان المؤلف يعرف على طول)،
والـAction هو الحكم الوحيد اللي بيقلب `published`. والـservice key بتاع
Supabase بيتحط في **GitHub Actions secrets** بس — عمره ما يدخل الريبو ولا
الكلاينت.

## ٣) الخطوات

كل خطوة بتتقفل لوحدها، وبالترتيب ده عشان كل واحدة بتعتمد على اللي قبلها.

### ٨.١ — الحكم (من غير سيرفر خالص)

`lib/level/level_check.dart`: دالة واحدة بتاخد `Level` وترجع حكم بأسباب:

- `requires` كله معروف للبيلد ده؛
- الحل المسجّل بيخلّص؛
- كل فكرة غلط **مبتخلّصش**، وفيه واحدة على الأقل (`Level.canBeChecked`)؛
- الجريات البخيلة مبتخلّصش (ينقلوا من `miserly_test.dart` لـ`lib` عشان
  التست والبوابة يشغّلوا **نفس** اللستة — نفس منطق `Playthrough`)؛
- حدود بسيطة: أبعاد معقولة، التأخير جوه مدى السلايدر، مفيش spawn جوه بلوك،
  الأبواب ≥ `minDoorHeight` (زي تستات `levels_test.dart` «the campaign holds
  together»)، وسقف على طول الحل (مثلاً ٩٠ ثانية) عشان البوابة متتعلّقش.

**التست:** الـ١٦ مرحلة كلهم بيعدّوا. ونسخ مكسورة منهم بتترفض **بالسبب
الصح**: من غير حل، حل مبيخلّصش، فكرة غلط بتخلّص، `requires` مجهول.

دي أهم خطوة في الـPhase، ومش محتاجة نت ولا حساب.

### ٨.٢ — القراية من السيرفر

`SupabaseLevels implements LevelSource` زي اللي في `backend-plan.md`، جوه
`LevelsThenExtras(BuiltInLevels(), …)` اللي موجودة ومختبرة.

- `timeout` ٤ ثواني، والفشل **ساكت** — اللاعب بياخد الحملة الأساسية.
- كاش على القرص لآخر نسخة ناجحة.
- **والكلاينت بيشغّل الحكم (٨.١) على كل مرحلة جاية قبل ما يعرضها.** السيرفر
  المفروض ميبعتش غير المقبول، بس اللعبة متصدّقش — ولو البيلد أقدم من المرحلة،
  `requires` بيرفضها.

الـpackage: `supabase_flutter`. بيشتغل على الويب والموبايل والديسكتوب — اتأكد
من آخر نسخة على pub.dev.

### ٨.٣ — الرفع والبوابة

- جدول `levels` (تحت) و`status`: `pending` → `published` / `rejected`.
- `tool/gate.dart`: بيسحب الـpending، يشغّل الحكم، يكتب `status` والسبب.
- `.github/workflows/gate.yml`: cron + `workflow_dispatch`.
- الرفع نفسه: من الورشة (`main_lab.dart`)، زرار «ارفع المرحلة دي» بيفحص
  محلياً الأول. محتاج تسجيل دخول (Supabase Auth، magic link) — **للرفع بس**.

### ٨.٤ — التيليمتري

زي القسم ١ في `backend-plan.md`: `attempts` بـ`device_id` مجهول. ده اللي
هيقول أنهي مرحلة ظالمة من غير ما تستنى حد يلعب قدامك.

### ٨.٥ — التأليف (ممكن يتأجل)

محرر مراحل جوه اللعبة. **مش شرط للـPhase** — الورشة بتقرا ملفات JSON
(`WARAYA_LEVELS=levels/`) وده كفاية للمؤلف الوحيد اللي عندنا دلوقتي.

## ٤) الـSchema

```sql
create table levels (
  id          text primary key,
  data        jsonb not null,             -- Level.toJson() كامل، بالحل
  author      uuid references auth.users,
  status      text not null default 'pending'
              check (status in ('pending', 'published', 'rejected')),
  verdict     text,                        -- سبب الرفض من البوابة
  checked_by  text,                        -- نسخة البيلد اللي حكمت
  sort_order  int not null default 1000,
  created_at  timestamptz not null default now()
);

alter table levels enable row level security;
create policy "anyone reads published" on levels
  for select using (status = 'published');
create policy "authors read their own" on levels
  for select using (auth.uid() = author);
create policy "authors submit" on levels
  for insert with check (auth.uid() = author and status = 'pending');
-- مفيش update من الكلاينت خالص. الـservice key بتاع البوابة بيعدّي الـRLS.
```

**`checked_by` مهم:** مرحلة اتقبلت ببيلد فيه قواعد مختلفة (زي لما الظل بقى صلب
بس وهو واطي) ممكن تبقى اتكسرت. لما قاعدة تتغيّر، البوابة تعيد تشغيل كل
المنشور.

## ٥) اللي محتاج منك قبل ٨.٢

١. **مشروع Supabase:** تعمله من supabase.com (الـfree tier كفاية)، وتدّيني
   الـProject URL والـanon key. الاتنين عامّين بطبيعتهم (الحماية في الـRLS)،
   فينفع يتحطّوا في الكود أو في `--dart-define`.
٢. **الـservice key:** **متدهولوش في الشات.** يتحط في GitHub → Settings →
   Secrets باسم `SUPABASE_SERVICE_KEY`، والـAction بس هو اللي يشوفه.
٣. **شبكة السيشن السحابية:** لو هنجرّب من هنا، الدومين `*.supabase.co` لازم
   يبقى مسموح في إعدادات الـenvironment.

٨.١ مش محتاجة أي حاجة من دول — ينفع تبدأ على طول.
